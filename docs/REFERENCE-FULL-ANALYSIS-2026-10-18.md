### 2.4 Оптимизация (эталон)

Замеченные в коде эталона приёмы (проверяются по коду, не по замерам):
- очередь фронта — бинарная куча на плоских массивах (`FlatBinaryHeap`), без замыканий в горячих циклах;
- буферы соседей переиспользуются (`nbuf`), а не создаются на каждую клетку;
- счётчики владельцев кешируются по малым идентификаторам (`smallID`), сравнения целочисленные;
- при подсчёте прилегающих клеток используется `forEach` по плотному хранению вместо генераторов (есть комментарий о профилировании);
- состояние исполнителей сериализуется со схемой (`zod`), что нужно для снимков и реплеев;
- клиент обновляет игрока по дельтам (`DiffPlayerUpdatePerf`), а не полным состоянием.

Что у нас: часть этих приёмов не сделана (клиентская отрисовка и горячие циклы не измерялись). Без перф-замеров утверждать «быстрее или медленнее» нельзя — это первым делом в плане.

## 3. Принципы адаптации (как строить, а не копировать)

1. **Сначала тесты, потом код.** Для каждой механики: golden-тест на текущее поведение, затем реализация по описанию из `COMBAT-REFERENCE` и `RADIAL-MENU-REFERENCE`, затем сверка чисел.
2. **Константы — данные.** Все числа из эталона — в одном месте (`BalanceConfig` или отдельный модуль правил), с комментарием-источником. Это позволяет менять баланс без правки алгоритма.
3. **Чистые функции для формул.** `attackLogic` — чистая функция от входа; её можно проверять без карты и игры.
4. **Наш стиль.** Табуляция в клиенте (как в текущих файлах), русские подписи в интерфейсе, без английских слов в русском интерфейсе.
5. **Документ в каждом шаге.** Что сделано, что проверено, что не проверено.

## 4. Этапы адаптации

Каждый этап заканчивается проверкой: `npm test`, `npm run build-prod`, для UI — браузер (сценарий `flow.mjs` в `/home/user/tools/browser`).

### Этап 0. Инфраструктура качества (первым)
- Golden-тесты текущего `AttackRules.attackLogic` (фиксируем, что есть, до изменений).
- Тесты исполнителя атаки на небольшой карте: захват, слияние, встречная атака, пустой фронт.
- Перф-замеры: время одного тика боя на карте World и Europe; время отрисовки клиента. Без этого оптимизацию не оценить.
- Проверка `typecheck` и линтера; решение, какие правила эталона переносить.

**Критерий:** тесты зелёные; замеры записаны в `docs/PERF-BASELINE-2026-10-18.md` (создать на этапе).

### Этап 1. Формулы боя (по `COMBAT-REFERENCE`)
- Тип рельефа в данных карты (или надёжный вывод из стоимости с тестом).
- Формула потерь и скорости против игрока (раздел 5.4 документа по бою) вместо таблиц.
- Случайная граница и приоритет фронта по описанию (раздел 3 документа по бою).
- Золотые значения для сетки входов: сверка с расчётом вручную для нескольких точек.

**Критерий:** golden-тесты совпадают с рассчитанными значениями; сценарии на картах дают ожидаемый темп (сравнение с эталоном по доле суши — `PARITY` раздел 1.5).

### Этап 2. Правила боя второго уровня
- Отступление (кнопка, задержка 20 тиков, малус 25 % против игрока).
- Поглощение игрока <100 клеток.
- Оборонительные постройки, предатели, радиоактивность, отключённый союзник в команде.

**Критерий:** по одной механике — тест и проверка в браузере.

### Этап 3. Радиальное меню (по `RADIAL-MENU-REFERENCE`)
- Модель меню: дерево элементов, состояние, уровни.
- Раскладка и геометрия, пересчёт при изменении окна, клиппинг к экрану.
- Подсказки, наведение, отключённые элементы, анимации переходов.
- Касание и мышь, кулдаун повторного открытия, блокировка карты под меню.
- Тесты модели меню (без DOM) и проверка в браузере на мыши и на сенсорном эмуляторе.

**Критерий:** меню работает на мыши и касании; тесты модели проходят; скриншоты сравниваются с описанием.

### Этап 4. Оптимизация по замерам
- Горячие циклы боя (очередь, соседи, счётчики) — по приёмам эталона, с замерами до и после.
- Клиент: обновление территории и подписей по изменениям, а не полным проходом (если замеры покажут).

**Критерий:** замеры улучшились; golden-тесты не сломаны; детерминизм сохранён.

### Этап 5. Дипломатия и отношения (отдельный раздел)
- Отношения при атаке, союзы, эмбарго — только после этапов 1–3, их разбор не выполнен в этом документе.
