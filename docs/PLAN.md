# Детальный план развития Frontline

Стратегия, уникальность, стек и бюджеты производительности — в
[VISION.md](VISION.md). Здесь — пошаговый план работ с критериями приёмки.
Главное правило: **мы не догоняем Terron по списку фич — мы делаем свой
вариант жанра**, исправляя ошибки предшественников.

## Незыблемые принципы

1. **Стабильность важнее фич.** Этап не готов, пока: тесты зелёны, сборка
   чистая, perf-бюджеты (VISION.md) не нарушены.
2. **Баланс — цифрами.** Все игровые числа — в
   `client/src/game/BalanceConfig.ts` (позже `packages/core`). Каждая правка
   баланса — отдельный коммит + bot-vs-bot проверка.
3. **Детерминизм.** Симуляция зависит только от сида и действий; случайность
   только через сид-PRNG ядра.
4. **Локализация RU+EN.** Ни одной строки в UI без ключа словаря.
5. **Лицензионная чистота.** Код и ассеты Terron/OpenFront не копируем —
   только идеи механик.

## Адаптивность (зафиксировано)
- Брейкпоинты: телефон < 640px, планшет 640–1023px, десктоп ≥ 1024px.
  Существующие `max-width: 767px / 1023px` в `base.css` — переходное состояние,
  новые правила пишутся по этим значениям.
- Тач-экраны (`pointer: coarse`): зона нажатия не меньше 44px (WCAG 2.5.5).
- Безопасные зоны: отступы через `env(safe-area-inset-*)`, высота через `100dvh`.
- Альбомный телефон (высота < 512px): логотип 110px, текст кнопок в одну строку.
- Проверено на 4 размерах: телефон 390×844, телефон альбом 844×390,
  планшет 768×1024, десктоп 1920×1080.
- Референс Terron: только публичные принципы (мобильная раскладка,
  крупные кнопки), код не копируем.

## Правила работы по этапам
- Один пункт плана — одна ветка-коммит с описанием; перед коммитом: `npm test`,
  `npx tsc --noEmit`, `npm run build-prod`, smoke-проверка в браузере.
- Ничего не удалять без явного подтверждения (см. историю с overpass-шрифтом).
- Версии ключевых зависимостей (vite, typescript) фиксируются точно, без `^`:
  Replit и другие хосты не всегда ставят версию из lock-файла.
- Нельзя использовать `class.name` как ключ: минификатор переименовывает классы
  и разные классы получают одно имя. Регистрация по объекту класса (см. TransactionExecutors).
- Белый экран после смены сборщика: сначала проверить консоль в браузере
  (headless Chromium с эмуляцией iPhone), потом менять код.
