- Ветка `arena/0330549f-ui-test` в основном репозитории `/home/user/UI-test` содержит незакоммиченные

## Журнал шага 2
- **2a (сделано, без изменения поведения):** реестры событий (`EventHandlerRegistry`, `Cached/Managed/Prioritized`)
  перенесены из `event/` в `util/events/`; `MathUtil` → `game/`; `DebugData` → `game/`; `VoxelRayTrace` → `map/`.
  Пересчитано 29 импортов скриптом. Проверка: `tsc` 0, тесты 43/43, `build-prod` 0. Нарушения 40 → 28.
- **Осталось (28):** `game → network` 18 (пакеты и `sendPacket` вшиты в симуляцию: нужен интерфейс команд);
  `map → network` 3; `network → ui` 2; `util → renderer` 2 (`UserSettingManager` → `DebugRenderer`, `GameTheme`);
  `util → network` 1 и `util → ui` 1 (`PathHandler.ts`); `event → game` 1 (`MapTransformHandler`).
- **Проверено и решено (2026-10-16):** `util/PathHandler.ts` НЕ мёртвый. Он подключается не импортом, а через
  маркер `//@module ui 1`: плагин `client/scripts/vite-plugins.js` собирает все файлы с маркером `@module` и генерирует
  загрузчик UI (`// BUILD_UI_MODULES_LOADER` в `main.ts`). `PathHandler` обрабатывает путь `/auth` (колбэк входа).
  Удалять нельзя. Это скрытая связь: граф зависимостей её не показывает. Вывод для архитектуры: загрузчик модулей
  надо сделать явным (список модулей с слоями в одном месте) — добавлено в шаг 2c.
- **Шаг 2c (новый):** заменить неявную загрузку по маркерам явным списком модулей по слоям; `PathHandler` перенести в
  слой `app` (он зависит от сети и UI, а `util` должен быть листом). Проверка: тест входа по `/auth` и обычной загрузки.
