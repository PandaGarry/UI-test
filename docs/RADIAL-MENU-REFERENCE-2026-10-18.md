# Радиальное меню эталона: разбор и разрыв с нашим (2026-10-18)

**Статус:** разбор выполнен по `src/client/hud/layers/RadialMenu.ts` (1402 строки), `MainRadialMenu.ts` (209), `RadialMenuElements.ts` (821) эталона, коммит `420f27a`. Наш код: `client/src/ui/element/RadialMenu.ts` (193 строки). Код не копируется: механика описана своими словами, константы — как факты для сверки.

**Общий вывод.** Эталонное меню — это модель дерева элементов с состоянием навигации, а не набор кнопок. Оно умеет вложенные уровни, кнопку «назад» в центре, подсказки, анимации переходов, таймеры на элементах, защиту от случайного повторного открытия и пересчёт позиции при изменении окна. Наше меню — один уровень из 3–4 секторов, открывается по касанию и закрывается по фону. Для адаптации нужна новая модель меню с тестами, а отрисовка и ввод строятся поверх неё.

## 1. Структура эталона

### 1.1 Слои
- `RadialMenuElements.ts` — описание элементов (данные): идентификаторы, подписи, цвета, условия доступности, действия, подменю, таймеры.
- `MainRadialMenu.ts` — контроллер игрового меню: собирает элементы по состоянию игры, обновляется раз в **500 мс** (`getTickIntervalMs() = 500`), передаёт параметры (`MenuElementParams`: игрок, тайл, возможности).
- `RadialMenu.ts` — класс `RadialMenu` (контроллер): отрисовка SVG, навигация по уровням, обработка ввода, анимации, подсказки, позиционирование.

### 1.3 Корневое меню: состав зависит от ситуации (исправлено при аудите 18.10)

Корень (`rootMenuElement`, id `root`) строит список при каждом открытии по состоянию клетки и игрока. Всегда **четыре** слота (фиксированного шестиэлементного списка нет).

Если клетка **своя** (`isOwnTerritory`):
1. Информация (`info`, действие: открывает панель игрока);
2. Удалить юнит (`delete`, действие, есть кулдаун `deleteUnitCooldown`);
3. Запрос союза (`ally_request`);
4. Строить (`build`, подменю со списком доступных юнитов).

Если клетка **чужая**:
1. Информация (`info`, действие);
2. Слот 2: если союзник и цель не отключена — **разорвать союз** (`ally_break`); иначе — **морская атака** (`boat`, действие `handleBoatAttack`, доступно только при возможности построить транспорт);
3. Слот 3: в окне продления союза — **продлить** (`ally_extend`, с таймером-дугой); иначе — **запрос союза** (`ally_request`);
4. Слот 4: если цель — дружественная (союзник или своя команда), отключённая не является, и нет доступных атакующих юнитов — **пожертвовать золото** (`ally_donate_gold`, действие); иначе — **атака** (`attack`, подменю со списком атакующих юнитов, как `createMenuElements(params, "attack")`).

Недоступность: `info` недоступен без выбранного игрока или в фазе спавна; `attack` недоступна в фазе спавна.

### 1.4 Центральная кнопка (`centerButtonElement`)
- Состояние `default`: действие зависит от фазы и цели. В фазе спавна — выбор места спавна (`handleSpawn`), кроме случайного спавна и своей клетки. Для дружественной цели — пожертвование войск: `floor(attackRatio × troops)` (доля из настроек интерфейса). Иначе — атака, если `canAttack`.
- Состояние `back`: возврат на предыдущий уровень.
- Недоступность: не суша; в фазе спавна — случайный спавн или своя клетка; дружественная цель — нет разрешения на пожертвование войск; иначе — нет `canAttack`.

## 2. Раскладка и геометрия

- Меню строится из секторов (дуг) вокруг центра; внутренний и внешний радиусы — по уровню (см. 1.2).
- Иконки элементов ставятся в середине дуги своего сектора.
- Центральная кнопка — круг радиуса `centerButtonSize`, в ней иконка `centerIconSize`. При наведении, если кнопка доступна, радиус растёт до ×1.2 за 200 мс (`onCenterButtonHover`), подсказки у неё нет.
- Когда открыто подменю, центральная кнопка меняет состояние на **«назад»**: радиус становится **×0.8** (`backButtonSize = centerButtonSize × 0.8`), иконка — стрелка назад (`backIconSize = centerIconSize × 0.8`), цвет — `#0f2744`.
- Состояние центральной кнопки: `default` или `back`. В `default` она выполняет действие главного меню, если элемент доступен (`centerButtonElement.disabled`), иначе курсор «не разрешено» и серая заливка `#999999`, иконка на 50 % прозрачности.

**Позиционирование** (`clampAndSetMenuPositionForLevel`):
- `margin = max(outerRadius, centerButtonSize) + 10`;
- позиция — точка касания, зажатая в пределах `[margin, окно − margin]` по каждой оси;
- если меню не помещается по оси (`2 × margin > размер окна`), оно центрируется по этой оси;
- при изменении размера окна позиция пересчитывается (`handleResize`), пока меню открыто.

Сравнение с нашим кодом: у нас позиция зажимается при открытии (`Math.min(Math.max(screenX, margin), innerWidth − margin)`), но не пересчитывается при изменении окна и не учитывает случай «не помещается». Радиусы у нас `INNER_R = 30`, `OUTER_R = 93`, тогда как в эталоне главное меню — 40/95.

## 3. Взаимодействие

### 3.1 Наведение (мышь)
- `mouseover`: показывается подсказка (`tooltipItems` или `tooltipKeys`); если элемент доступен и не идёт переход, сектор подсвечивается фильтром `brightness(1.5)`.
- `mouseout`: подсказка скрывается; таймер `submenuHoverTimeout` сбрасывается; цвет возвращается: доступный — цвет элемента с непрозрачностью **0.82**, недоступный — `disabledColor` с непрозрачностью **0.4**.
- Подсказка следует за курсором: `left = pageX + 10`, `top = pageY + 10`.
- Во время перехода между уровнями подсветка не применяется.

### 3.2 Нажатие
- `click`: `stopPropagation`; если элемент недоступен или идёт переход — ничего; иначе звук «click» (`PlaySoundEffectEvent`).
- Если на уровне ≥1 нажат элемент не выбранного родителя — игнор (не даёт случайно выбрать соседний элемент).
- Если у элемента есть подменю — `navigateToSubMenu`, выбранный элемент запоминается (`selectedItemId`), центральная кнопка переходит в состояние «назад».
- Иначе — действие `action(params)`, затем меню скрывается (`hideRadialMenu`), состояние перехода сбрасывается принудительно.
- `touchstart`: `preventDefault` и `stopPropagation`, затем та же логика, что у клика. Это решает двойные срабатывания на сенсорных экранах.

### 3.3 Центральная кнопка
- В состоянии `default` — действие главного меню, если доступно.
- В состоянии `back` — `navigateBack()` с флагом `navigationInProgress`.
- Наведение на центр (`onCenterButtonHover`) увеличивает кнопку ×1.2 за 200 мс (подсказку не показывает — исправлено при аудите 18.10).

### 3.4 Навигация по уровням
- `navigateToSubMenu(children)`: кладёт текущий список в стек (`menuStack`), рендерит новый уровень, анимирует переход (`animateMenuTransitions`, `renderAndAnimateNewMenu`, `animateExistingMenu`) за `menuTransitionDuration` (300 мс).
- `navigateBack()`: снимает уровень со стека и возвращает предыдущий.
- Флаги: `isTransitioning`, `navigationInProgress`, `currentLevel`, `menuStack`, `currentMenuItems`.
- Глубина ограничена `maxNestedLevels` (3).

### 3.5 Повторное открытие
- `reopenCooldownMs = 300`: после закрытия (`lastHideTime`) повторное открытие запрещено на 300 мс (`isReopeningAllowed`). Это защищает от случайного открытия при быстром «двойном тапе».

### 3.6 Закрытие
- Нажатие на фон, закрытие действием, сброс (`resetMenu`) при смене состояния игры.
- Для нас: закрытие по фону есть (`pointerdown` на корне), сброса при смене состояния нет (не проверено).

## 4. Визуальные состояния

- **Доступный элемент:** цвет по элементу, непрозрачность 0.82, курсор-указатель.
- **Недоступный элемент:** серый `disabledColor`, непрозрачность 0.4.
- **Наведённый элемент:** яркость ×1.5 (`brightness(1.5)`).
- **Выбранный родитель** (на уровне ≥1 подсвечивается тот, из которого открыто подменю): не сбрасывается при `mouseout` (чтобы не терять контекст).
- **Таймер-дуга** (`timerFraction` 0..1): сектор заливается градиентом `timer-gradient-<id>`, показывая оставшееся время (пример — `ally_extend`).
- **Иконка продления союза** (`renderAllyExtendIcon`, `refreshAllyExtendIcon`): отдельный состав состояний (`getAllyExtendStateKey`).
- Подсказки: стиль `tooltipStyle` с раскраской стоимости (`.radial-tooltip .cost`).

## 5. Производительность и корректность

- Меню не перерисовывает весь SVG при каждом кадре: обновление раз в 500 мс по состоянию игры (`MainRadialMenu`), и перерисовка уровня только при переходе.
- Обработчики вешаются на каждый сектор (`arcs.each`), а не на весь контейнер; на `mousemove` обновляется только подсказка.
- Все таймеры (`submenuHoverTimeout`, `backButtonHoverTimeout`) очищаются при уходе курсора и при закрытии.
- Состояние навигации хранится явно (стек, уровень, флаги), что позволяет проверять переходы тестами (в эталоне есть тесты клиента `tests/client/components`, `tests/client/controllers`; для меню отдельных тестов не найдено — не проверено глубже).

## 7. План адаптации меню (по этапам общего плана)

Этап 3 общего плана (`REFERENCE-FULL-ANALYSIS-2026-10-18.md`):

1. **Модель меню без DOM.** Дерево элементов, стек уровней, состояние центра, доступность, кулдаун. Тесты: переходы вперёд/назад, лимит вложенности, игнор клика по неродительскому элементу, кулдаун, закрытие.
2. **Геометрия без DOM.** Радиусы по уровню, расчёт центров иконок, зажим позиции с учётом размера окна. Тесты: расчёт для разных размеров окна.
3. **Отрисовка.** SVG по модели, подсказки, наведение, переходы. Проверка в браузере (мышь) и с эмуляцией касания.
4. **Элементы игры.** Перенос элементов по описанию (раздел 1.3) с русскими подписями, без английских слов. Иконки — собственные.
5. **Обновление.** Раз в 500 мс при открытом меню, сброс при смене игры.

Критерии: тесты модели зелёные; меню работает на мыши и касании; при изменении окна позиция корректна; подсказки не перекрывают меню.
