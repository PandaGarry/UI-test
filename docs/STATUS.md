## 2026-10-16: касание не открывало/не атаковало (причина найдена и исправлена)
- Причина: при касании меню открывается прямо под пальцем, и браузер синтезирует `click` по элементу под пальцем. Этим элементом оказывалась центральная кнопка «Атака» нового меню, она вызывала атаку и закрывала меню. Итог: касание по вражеской клетке сразу отправляло атаку (20%) без меню; при этом тап по врагу в тесте «не открывал меню». Мышь не страдала: её `click` уходит на общего предка mousedown/mouseup.
- Исправлено (RadialMenu.ts, `onPressedClick`): кнопки меню реагируют только на клик, который начался нажатием именно на этой кнопке.
- Список атак теперь открывается при отправке атаки (событие `arena:attack-sent`, GameHud.ts).
- Проверка (scripts/ui-tests/enemy2.mjs, 80 тапов, касание и мышь): открыто 80/80, призрачных отправок при открытии 0, доступных нажатий 16 из 16 отправлены, тихих отказов при доступной атаке 0.
- Открыто: один тихий случай (иконка «Атака», атака была доступна при открытии, отправки не было) в прогоне из 8 доступных; не воспроизведён в 16. Возможная причина: доступность меню фиксируется при открытии, граница может измениться до нажатия, и `attackAction` молча уходит в морскую ветку без точки запуска. Нужен счётчик таких отказов.
- Открыто: «No suitable tile found» (морская ветка) — то же место.
